## 记号与约定

### 总线（第6章）

- **总线**：模块之间或设备之间传送信息的一组公用信号线，分时共享，因此会争用（p203）。
- **层次**（p203）：内部总线（片内总线）；系统总线（又叫内总线、板级总线、底板总线）；I/O 总线（又叫通信总线、设备总线、外总线）；局部总线。
- **四个特性**（p204）：物理特性、功能特性、电气特性、时间特性。小结里写成"物理、功能、电气、机械"（p228），两处不一致，题目以正文四项为准。
- **总线宽度**：第6章没有单独定义"总线宽度"。正文在功能特性里说：地址总线宽度决定可直接访问的地址空间，数据总线宽度决定一次交换的数据位数（p204）。解析选择题把"数据总线的宽度"归到功能特性（解析 p101 第4题）。
- **总线带宽**：总线本身能达到的最高传输速率（p204）。公式 `Dr = D/T = D×f`，D 是一个总线周期传送的数据量，T 是总线周期，f 是总线时钟频率；例 6.1 默认"一个总线周期 = 一个时钟周期"（p205）。单位写 MB/s，M 取 10^6（例 6.1：4B×33×10^6/s = 132MB/s）。注意例 8.5 里明确取 K=2^10、M=2^20（p289），两章不统一。
- **主方/从方**：主方（主设备）启动总线周期，从方只响应；主方持续控制总线的时间叫总线占用期（p211–212）。
- **串行传送**：一条传输线，脉冲传送，按位时间逐位发送，低位在前、高位在后；发送端并-串变换叫"拆卸"，接收端串-并变换叫"装配"（p208–209）。
- **并行传送**：每位一条线，电位传送（p209–210）。系统总线必须并行（p208）。
- **波特率**：教材把"每秒钟传送的比特位数"称为波特率（p211），全书没有出现"比特率"一词，不区分两者。每位时间 `Td = 1/波特率`。
- **串行帧格式**（计算用）：例 6.2 = 起始位 1 + 数据位 8 + 停止位 1 = 10 位，无校验（p211，图 6.9）。习题里是 7 位数据 + 1 位校验 + 1 位起始 + 1 位停止 = 10 位（p229 第3、10题）。字符速率 = 波特率 ÷ 每帧位数。空闲与停止位为高电平，起始位为低电平（图 6.9；解析 p109 图 6.7）。
- **集中式仲裁信号**（p212）：BR 总线请求，BG 总线授权，BS 总线忙（BS=1 表示总线正被使用）。独立请求方式下每个设备一对 BRi、BGi。
  - 链式查询（教材也叫菊花链查询）：BG 串行下传；离仲裁器越近优先级越高；线少、易扩充；对链路故障敏感、优先级固定。
  - 计数器定时查询：仲裁器把计数值经一组设备地址线发给各设备；从 0 计数则优先级固定，从中止点计数则各设备优先级相等，初值可由程序设置。
  - 独立请求：仲裁器内有排队电路；响应最快、优先次序可编程、可屏蔽某个请求；当代总线标准普遍采用。
  - 控制线数量的比较只在解析里有：n 个设备，独立请求 2n 根，链式查询 2 根，计数器查询约 log2 n 根（解析 p105）。
- **分布式仲裁**（p213–214）：没有中央仲裁器；每个主方有仲裁号（图 6.11 里叫竞争号 CN）和仲裁器；号大者胜；AB 为仲裁总线，W 为逐位的"竞争得胜"信号。
- **定时协定**（p214–217）：同步、异步、半同步、周期分裂式（文中也叫分离式）。异步"建立在应答式或互锁机制基础上"。教材第七版正文**没有**"不互锁/半互锁/全互锁"的分类；只有解析 p107 在一道题的答案里用了"异步双向全互锁"。
- **数据传送模式**（p217–218）：读、写；块传送（CPU 对存储器的块传送叫突发/猝发式传送，块长一般为数据线宽度的 4 倍）；写后读、读修改写；广播（一主写多从）、广集（多个从方数据在总线上做 AND/OR）。
- **一次总线传送的五个阶段**（p214）：请求总线 → 总线仲裁 → 寻址（目的地址）→ 信息传送 → 状态返回（或错误报告）。

### 输入/输出（第8章）

- **接口**：又叫适配器；**端口**是接口里能被 CPU 直接访问的寄存器，分命令口、状态口、数据口（p256–257）。
- **统一编址**：端口和内存单元一起编址，用访存指令访问，不需要专门的 I/O 指令。**I/O 独立编址**：两套地址，访问 I/O 用专门的 I/O 指令组（p257）。
- **接口与外设之间**三种传送（p258）：无条件传送（零线握手）、应答方式（异步，双线握手：选通/请求 + 应答）、同步传送。
- **CPU 与接口之间**五种方式（p258–260，图 8.2）：无条件传送（简单 I/O）、程序查询（轮询）、程序中断、DMA、通道与输入输出处理器（IOP；另有外围处理器 PPU）。图 8.2 把程序查询和中断归为"主要由程序实现"，DMA 和通道/IOP 归为"主要由硬件实现"。
- **异常与中断**（第七版定义，p263）：广义的异常 = 中断 + 狭义的异常。中断由处理器之外的硬件触发，也叫**外中断**；狭义的异常由机器内部原因引起，也叫**内中断**。
- **中断源**：引起中断的事件。**断点**：主程序被打断的位置。**公操作**：一条指令结束后 CPU 做的操作（中断处理、取下条指令）（p264–265）。
- **中断周期**：响应中断、关中断、保存断点等由硬件完成的阶段；这些在程序里看不到的操作叫"**中断处理的隐操作**"（p266）。教材不用"中断隐指令"这个词（统考题里用）。
- **保存现场**：把 PC 以及当前指令结束后的 CPU 状态（寄存器、状态标志）存入堆栈（p265）。图 8.6 把"保存 PC"画在硬件的中断周期里，把"保存 CPU 现场"画在软件的服务子程序里。
- **五个触发器**（p267–268）：BS 工作（忙）标志；RD 准备就绪（中断方式下兼作中断源触发器）；EI 允许中断（在接口里，程序可置位，EI=1 才能发请求）；IR 中断请求（在 CPU 里）；IM 中断屏蔽（在 CPU 里，**IM=1 关中断，IM=0 开中断**）。
- **INTA**：中断响应信号。
- **向量中断**：硬件自动给出中断向量地址。**中断向量** = 中断服务程序的入口地址（有的系统还含初始 PSW）；**向量地址** = 该向量在中断向量表里的位置（p266，图 8.7）。**查询中断**：进公共服务程序后由软件查询中断源（p266–267，图 8.8）。
- **单级中断**：所有中断源同一级，服务期间不允许任何其他中断打断（p268）。**多级中断**：分级，高级可打断低级，嵌套执行；一维 = 每级一个中断源，二维 = 每级多个中断源；同级内不嵌套（p270）。
- **中断请求寄存器 / 中断屏蔽寄存器**：n 级中断对应 n 个 IR、n 个 IM。某级被响应后，把本级和更低级的屏蔽位置 1（关闭），更高级的清 0（开放）（p270）。屏蔽位 **1 = 屏蔽，0 = 允许**（p270；习题 8，p290）。
- **DMA 三种传送方式**（教材名称，p276）：① 成组连续传送方式（停止 CPU 访存）；② 周期挪用方式（单字传送方式、周期窃取方式）；③ 透明 DMA 方式（DMA 与 CPU 交替操作方式、总线周期分时方式）。解析沿用旧称：停止 CPU 访问内存、周期挪用、DMA 与 CPU 交替访内（解析 p126–127）。站点正文用教材名称，旧称作别名。
- **DMA 控制器六部件**（p278–279）：内存地址计数器、字计数器、数据缓冲寄存器、DMA 请求标志、控制/状态逻辑、中断机构。总线请求 HOLD，总线响应 HLDA。
- **DMA 三阶段**（p279–280）：传送前预处理、正式传送、传送后处理。
- **选择型 DMA 控制器**：物理上接多个设备，逻辑上同一时间只为一个设备服务，适合高速设备。**多路型**：逻辑上也允许多个设备同时工作，字节交叉传送，适合慢速设备（p280–281）。
- **通道**：正文只在 8.1.4 用一段话定位（有自己指令和程序的简化处理器，p260），细节放在 p283 页边二维码"通道方式"里。通道类型（选择通道、数组多路通道、字节多路通道）只在解析里有（解析 p127）；教材习题 5（p290）却考通道功能和类型。

## 过程与步骤

### 1. 集中式仲裁的三种次序（p212–213，图 6.10）

**链式查询**
1. 要用总线的设备在公共 BR 线上发请求。
2. 仲裁器发出 BG。BG 从离仲裁器最近的接口开始，一个接口一个接口往下传。
3. BG 到达的接口没有请求：继续下传。
4. BG 到达的接口有请求：BG 不再下传，该接口获得总线控制权（BS 置 1）。
教材只有文字，没有数值例，并把"画出链式查询电路"留作思考题。解析 p109–110 给了门级电路和七步过程：信号低有效（BB 总线忙、BR 请求），每个部件有 BGI 输入和 BGO 输出；BR 有效且总线空闲时仲裁器发 BG；未申请的部件把 BG 传下去；申请者在收到 BGI 上升沿时接管总线、封锁 BGO 并拉低 BB；用完后释放 BB。占用期间更高优先级的部件也抢不到（非强占）。

**计数器定时查询**
1. 设备经 BR 发请求。
2. 仲裁器在 BS=0 时启动计数器，计数值经设备地址线发到所有接口。
3. 每个接口比较计数值和自己的设备地址；相等且有请求的设备把 BS 置 1，获得总线，计数停止。
4. 下一轮的计数起点决定优先级：从 0 开始 = 固定优先级；从中止点开始 = 循环、机会均等；也可由程序设初值。

**独立请求**
1. 设备 i 发 BRi。
2. 仲裁器的排队电路按优先次序选一个，回 BGi。
没有逐个查询的过程，所以响应最快。

### 2. 分布式仲裁（p213–214，图 6.11）

1. 参与竞争的主设备把竞争号 CN 取反后送到仲裁总线 AB，形成"线或"：AB 某位为低表示至少有一个设备该位为 1。
2. 从最高位 b7 到最低位 b0 逐位比较。第 i 位得胜条件：上一位已得胜（W(i+1)=1），并且 CNi=1，或者 CNi=0 且 ABi 为高。
3. 某位败了（Wi=0）就一直往下传，它后面的低位不再送上 AB。
4. 败者自动撤号，过程反复进行直到稳定，最后 AB 上留下最大的竞争号。
教材例子是 8 个设备、8 位号，没有给具体数字的竞争过程。

### 3. 总线定时（p214–217）

**同步读**（图 6.12，三个时钟周期）：T1 CPU 放地址和状态信号，可发启动信号（图中"地址允许"）；T2 发读命令；存储器经一个周期的延迟，在 T3 放数据和认可信息，CPU 读取。
**同步写**：T2 开始 CPU 把数据放上数据线，数据稳定后发写命令，存储器在 T3 存入。
**异步读**（图 6.13(a)）：① CPU 发地址和读状态信号 → ② 稳定后发读命令 → ③ 存储器译码，把数据放上数据线 → ④ 数据稳定后存储器使确认线有效 → ⑤ CPU 读走数据，撤销读状态信号 → ⑥ 存储器撤销数据和确认 → ⑦ CPU 撤销地址。
**异步写**（图 6.13(b)）：CPU 同时放数据、状态和地址 → 发写命令 → 存储器写入并使确认有效 → CPU 撤销写命令 → 存储器撤销确认。
**半同步**（图 6.15）：基本周期 T1–T4；在 T3 前沿检测 READY，有效则进 T4，无效则插入等待周期 Tw，并在每个 Tw 前沿再检测，直到有效。
**周期分裂式**：读周期拆成两个子周期。第一个子周期主方发地址和命令后立即让出总线；从方内部准备好数据后自己申请总线，在第二个子周期把数据送回。写只需第一个子周期。读的双方都要当总线主方。

**例 6.3**（p216，图 6.14）：独立请求加菊花链的二维结构，异步握手。要点是七个事件的因果顺序：设备升 BRi → CPU 升 BGi → 设备升 SACK（解析版本同时降 BRi）→ CPU 降 BGi → 等现行主设备降 BBSY 后，新设备升 BBSY 成为主设备 → 用完后降 BBSY 和 SACK。

### 5. 输入/输出的一般过程与程序查询（p257，p262–263）

输入三步：CPU 放地址选设备 → 等数据有效 → 从数据总线读入寄存器。输出三步：放地址 → 放数据 → 设备认为有效后取走。
**程序查询五步**（p262）：① 向设备发命令字，请求传送 → ② 读状态字 → ③ 检查状态标志 → ④ 未就绪则重复 ②③，直到 Ready → ⑤ 传送数据，同时把状态标志复位。
**多设备轮询**（图 8.4）：主程序周期性调用查询子程序，依次测试设备 1–4 的 Ready；为 1 就执行该设备的服务子程序，然后接着查下一个；全部查完返回主程序断点 m。先查传输率高的设备。服务子程序做四件事：传送数据、修改内存地址、修改传送字节数、状态分析。
解析 p128–129 的对比题：如果服务完一个设备就直接回主程序，排在后面的设备可能长期得不到服务；改为回到查询子程序继续往后查。

### 6. 单级中断处理过程（图 8.6，p264–266）

教材流程图的顺序如下，括号里是谁做：
1. 取指令 → 执行指令（指令周期，硬件）。
2. 指令执行完，判断有无中断请求。无：取下一条指令。有：进入中断周期。
3. 响应中断，发 INTA（硬件）。
4. 关中断，"中断屏蔽"置位，IM=1（硬件）。
5. 找出中断源，保存 PC，即保存断点（硬件）。
6. 获取中断服务程序入口地址，转移到中断服务子程序（硬件）。
7. 保存 CPU 现场（软件）。
8. 设备服务（软件）。
9. 恢复 CPU 现场（软件）。
10. 开中断，IM=0（软件）；随后中断返回，回到主程序的下一条指令。
教材的四点说明（p265–266）：只在当前指令执行完、转入公操作时才受理中断；现场保存到堆栈；用"中断屏蔽"触发器防止新请求打乱，服务程序末尾安排开中断和中断返回两条指令，硬件保证返回指令执行后才受理新请求；响应、关中断、保存断点一定由硬件做，找中断源、排队判优、取入口地址可以硬件做，也可以由软件在进入服务程序时做。
单级流程图里保存现场之后没有"开中断"这一步，因为单级不允许嵌套。
**响应条件**（解析 p132）：IM 开放；IR=1；接口的 EI=1；当前指令执行结束。
**接口上的 ①–⑩**（图 8.9，p268）：① 程序启动外设，BS 置 1、RD 清 0 → ② 接口向外设发启动信号 → ③ 数据从外设进缓冲寄存器 → ④ 外设动作结束，RD 置 1 → ⑤ EI=1 时接口发中断请求 → ⑥ 指令末尾 CPU 把请求收进 IR → ⑦ IM=0 时 CPU 发响应信号并关中断 → ⑧ 转入该设备的服务程序入口 → ⑨ 服务程序用输入指令把缓冲寄存器的数据读进 CPU → ⑩ CPU 发信号 C，把 BS、RD 复位。

### 7. 单级中断源识别：串行排队链（图 8.11，p269–270）

三个中断源，优先级 IR1 > IR2 > IR3。排队输入 INTI（低有效）有效时 IS1=1。IR1 有请求：INTA 到来时门 7 打开，编码器把该源的向量码送上数据总线，同时封锁后面的 IS2、IS3。IR1 无请求：选中信号往下传给 IS2，依次类推。图中三个向量码是 001010、001011、001000。

### 8. 多级中断（p270–273）

**规则**：n 级中断有 n 位请求寄存器和 n 位屏蔽寄存器；屏蔽寄存器的内容属于现场，响应时要保存并设置新值；响应某级后屏蔽本级和更低级，开放更高级；现场用堆栈保存；先响应哪一级由硬件排队电路决定（独立请求），级内再用链式查询。
**排队例**（p272，图 8.13）：源 1 最高、源 4 最低，请求寄存器 1111，屏蔽寄存器 0010 → 进入排队器的是 1101 → 排队器输出 1000 → 编码器给出源 1 的向量地址。
**例 8.2**（p272–273，图 8.12(b)）：三级九个设备，第 2 级 A B C、第 1 级 D E F、第 0 级 G H I。
- 优先次序 A→B→C→D→E→F→G→H→I→CPU（CPU 的主程序最低）。
- 执行 B 的服务程序时 IM2IM1IM0 = 111；执行 D 的服务程序时 = 011。
- IM 按级屏蔽，不能单独屏蔽一级里的某个设备；要单独禁止就把该设备接口的 EI 清 0。
- 想让 C 一请求就被响应：把 C 单独提到新的最高级（第 3 级），令 IM3=0。
**例 8.3**（p273）：只看 A、B、C 的单级链。设一条指令时间为 TM，三者同时请求时：tA = 2TM + TDC + TS + TA + TR，tB = 2TM + 2TDC + TS + TB + TR，tC = 2TM + 3TDC + TS + TC + TR；T = tA + tB + tC 是达到中断饱和的最小时间，极限频率 f = 1/T。2TM 是取指加执行（解析 p132 图 8.7）。

**屏蔽字、处理次序、运行轨迹**：教材正文没有"屏蔽字"的例题，也没有 CPU 运行轨迹图的画法说明。能依据的只有：p270 的置 1/清 0 规则、图 8.12(a) 的嵌套锯齿示意图、习题 8（p290，五级中断，要求填屏蔽位表并画"进入各级中断处理程序的过程示意图"）。解析第8章没有这类题；统考 2011 年有一道同型选择题（解析 p201）。
按教材约定（1 = 屏蔽）可得的做法，以习题 8 的条件为例（响应次序 L0 > L1 > L2 > L3 > L4，处理次序改为 L1→L3→L0→L4→L2）。以下是按规则推出的，不是教材给的答案：
1. 每一行是一个处理程序，每一列是一级。该程序要屏蔽自己和处理次序在自己之后的级，置 1；处理次序在自己之前的级置 0。
2. 得到（列序 L0 L1 L2 L3 L4）：L0 程序 10101；L1 程序 11111；L2 程序 00100；L3 程序 10111；L4 程序 00101。
3. 轨迹：五级同时请求。按响应次序先进 L0 → L0 开放了 L1、L3，L1 先打断 L0 → L1 做完回 L0 → L3 再打断 L0 → L3 做完回 L0 → L0 做完回主程序 → 剩 L2、L4，先响应 L2 → L4 打断 L2 → L4 做完回 L2 → L2 做完回主程序。完成的先后就是 L1、L3、L0、L4、L2。
4. 检查：一行里 1 的个数越多，处理次序越靠前（5、4、3、2、1 个）。

### 9. DMA（p275–283）

**四项基本操作**（p276）：外设就绪后发 DMA 请求 → CPU 响应，DMA 控制器接管总线 → 控制器给出内存地址、计数、传送 → 向 CPU 报告结束。
**请求握手**（p279）：设备准备好一个字 → "DMA 请求"标志置 1 → 控制/状态逻辑向 CPU 发 HOLD → CPU 回 HLDA → 控制/状态逻辑发 DMA 响应，把请求标志复位。
**三阶段**（p279–280，图 8.17）：
1. 预处理（CPU 执行几条 I/O 指令）：测试设备状态；送设备号并启动设备；向内存地址计数器送起始地址；向字计数器送字数。之后 CPU 继续执行主程序。
2. 正式传送（硬件）：设备发 DMA 请求 → HOLD → CPU 在当前总线周期结束后响应，总线驱动器进入高阻 → 控制器送内存地址，传一个字，地址计数器加 1，字计数器计数 → 未传完则循环 → 传完后发中断请求。
3. 后处理（CPU 响应中断，执行服务程序）：校验送入内存的数据；决定继续还是结束；检查传送中是否出错。
DMA 请求在一个总线周期结束时就能响应，中断请求要等一条指令结束。
**三种传送方式的差别**（p276–278，图 8.15）：成组连续传送时 CPU 在整批数据期间不访存；周期挪用每次请求只占一个或几个内存周期，CPU 同时要访存时 I/O 优先，但每次都有申请、建立、归还总线的过程，对控制器而言一个字要 2–5 个内存周期；透明 DMA 把一个 CPU 周期分成 C1（给 DMA）和 C2（给 CPU），不需要申请总线，教材举例 CPU 周期 1.2μs、内存存取周期 0.6μs。
**多路型一次请求**（p282）：控制器把请求转给 CPU → CPU 在适当时刻响应 → 控制器给优先权最高的请求发响应，用它的地址寄存器驱动地址总线，发读/写信号，传一个字节，地址寄存器和长度寄存器加 1 或减 1。
**例 8.4**（p283，图 8.21）：磁盘每 30μs、磁带每 45μs、打印机每 150μs 请求一次，优先权磁盘 > 磁带 > 打印机，每次服务 5μs。图中打印机先请求（T1）；磁盘和磁带同时请求时先磁盘（T2）后磁带（T3）；120μs 内磁盘 4 次（T2、T4、T6、T7），磁带 3 次（T3、T5、T8），打印机 1 次（T1），控制器还有空闲。

### 10. I/O 性能与系统设计（p257–258，p288–289）

**例 8.1**：程序 100s，其中 CPU 90s、I/O 10s；CPU 每年快 50%，I/O 不变。逐年 CPU 时间 90、60、40、27、18、12，五年后总时间 22s，I/O 占比从 10% 升到 45%。
**设计三步**（p288）：找出 I/O 路径上效率最低的部件 → 按所需带宽配置它 → 再配置其余部分去支持这个带宽。
**例 8.5**：CPU 3×10^9 指令/秒，每次 I/O 共 300 000 条指令 → 10 000 次/秒；总线 1000MB/s，每次 64KB → 16 000 次/秒；CPU 是瓶颈。每次磁盘 I/O = 6ms + 64KB÷75MB/s ≈ 6.85ms → 每盘 146 次/秒 → 需 69 个磁盘；每个 SCSI 控制器最多 7 盘 → 10 个控制器。

## 题型分类

数量栏的写法：教材 = 例题数 + 习题数；解析 = 第6章或第8章的选择题数 + 分析题数。归类是按题意人工划分的，个别题跨两类，只记入主类。

| 题型 | 已知什么 | 求什么 | 典型参数 | 数量（教材 / 解析） | 标准解题步骤 | 常见错误 |
|---|---|---|---|---|---|---|
| 总线带宽计算 | 每个总线周期传送的字节数或位数，时钟频率，周期与时钟的关系 | 带宽 MB/s | 4 字节 33MHz；64 位 66MHz；8 字节 70MHz | 例 1 + 习题 1（第19题）/ 分析 1（选择第9题涉及带宽定义，计入概念类） | 位数化成字节 → 确认一个总线周期含几个时钟周期 → Dr = D×f | 位和字节不换算；把 M 当 2^20；总线周期不等于时钟周期时忘了除 |
| 串行波特率与字符速率 | 字符速率或波特率，帧格式 | 波特率、每位时间，或每秒字符数 | 120 字符/秒、10 位帧；9600 波特、7+1+1+1 位 | 例 1 + 习题 1（第10题）/ 选择 1 | 数清一帧的位数（起始、数据、校验、停止）→ 波特率 = 字符速率 × 帧位数 → Td = 1/波特率 | 漏算起始位或校验位；把字节速率当波特率 |
| 异步串行字符波形 | 字符、数据位数、校验方式、起止位数 | 画波形 | 7 位数据偶校验；8 位数据奇校验 | 习题 1（第3题）/ 分析 1（第12题） | 查 ASCII → 数 1 的个数定校验位 → 起始位低，数据低位在前，校验位，停止位高 | 高位先发；校验位按奇偶弄反；空闲电平画成低 |
| 仲裁方式判别与比较 | 结构图或文字特征 | 判断哪种仲裁，比较响应速度、线数、故障敏感度、优先级是否可变 | 链式 / 计数器 / 独立请求 / 分布式 | 习题 5（第5、6、7、9、17题）/ 选择 1 + 分析 6 | 看有没有串行的 BG、有没有设备地址线、是不是每设备一对线 → 套各自优缺点 | 把计数器查询当成优先级一定固定；记错线数 |
| 定时方式与时序图分析 | 时序图或文字描述 | 判断同步/异步，说明各信号先后与因果 | BR、BG、SACK、BBSY；MSYN、SSYN；T1、T2 与 READY | 例 1 + 习题 2（第8、18题）/ 选择 2 + 分析 5 | 有无公共时钟 → 有无应答信号 → 按因果给每个跳变编号 | 把半同步的 READY 当成异步；颠倒撤销顺序 |
| 总线结构与基本概念 | 概念陈述 | 选择、填空、简答 | 单总线/多总线，地址线、控制线功能，特性归属 | 习题 6 / 选择 12 + 分析 3 | 回到定义 | 特性归属混淆（功能特性与电气特性）；解析里的三总线结构教材正文没有 |
| PCI、PCIe、鲲鹏（描述性） | 产品事实 | 填空、判断、简答 | 三种桥、猝发式传送、同步时序、集中式仲裁 | 习题 5 / 选择 5 + 分析 3 | 记忆 | — |
| I/O 方式的概念与比较 | 场景或陈述 | 选哪种方式，比较查询、中断、DMA、通道 | 串行工作与并行工作；适用设备速度 | 习题 3（第1、12、14题）/ 选择 9 + 分析 4 | 按"谁控制传送、CPU 是否等待、数据是否经过 CPU"三问区分 | 以为 DMA 期间 CPU 完全不能执行程序；以为 DMA 淘汰了中断 |
| 程序查询接口与流程 | 接口图或流程图 | 说明输入输出过程，指出轮询流程的问题与改进 | 忙、就绪两个触发器；四台设备 | 0 / 分析 2（第11、12题） | 按"启动 → 查状态 → 就绪后传送 → 复位"叙述 | 漏掉状态标志复位 |
| 中断基本概念与流程 | 概念陈述或要求画图 | 响应条件、各触发器作用、流程图、现场保存范围 | IM、IR、EI、RD、BS；向量地址 | 习题 3（第2、9、13题）/ 选择 7 + 分析 4 | 分清硬件隐操作与软件服务程序 → 按图 8.6 顺序写 | 把中断向量和向量地址混为一谈；把 IM=1 当开中断；保存断点写成由软件完成 |
| 二维多级中断的 IM 状态与调整 | 图 8.12 式的结构，正在服务的设备 | IM 各位的值，能否被打断，如何让某设备最优先 | 三级九设备 | 例 1 + 习题 2（第6、11题）/ 分析 1 | 找设备所在级 → 本级及更低级置 1，更高级置 0 → 单个设备用 EI 控制 → 要抢占就升到新的最高级 | 以为同级内可以嵌套；想用 IM 屏蔽单个设备 |
| 中断饱和时间与极限频率 | 指令时间、链延迟、保存/恢复现场时间、各设备服务时间 | 每个设备的处理时间、总时间 T、f = 1/T | TM、TDC、TS、TR、TA–TC；或 t1–t4 | 例 1 + 习题 2（第3、7题）/ 分析 1 | 每个设备 = 指令时间 + 中断周期（链延迟按位置累加）+ 保存现场 + 服务 + 恢复现场 → 求和 → 取倒数 | 链延迟不按位置累加；漏掉等当前指令执行完的时间 |

## 建议的交互页面

按对期末复习的价值排序。

1. **中断屏蔽字与嵌套轨迹**
   困惑："响应优先级是硬件定死的，为什么改屏蔽字就能改处理次序？"
   模型：可编辑的屏蔽字矩阵（1 = 屏蔽）加时间轴。给定同时到达的请求，逐步显示当前程序、屏蔽寄存器、被挂起的请求和堆栈，画出锯齿轨迹。
   练习：给处理次序填屏蔽字；给屏蔽字反推处理次序；给请求到达时刻画轨迹。页面注明这是教材习题 8 的题型，正文没有例题。
2. **单级中断的一次完整过程**
   困惑："关中断、保存断点、保存现场、开中断，各由硬件还是软件做，先后是什么？"
   模型：图 8.6 流程图与图 8.9 接口图联动，按 ①–⑩ 单步，高亮 IM、IR、EI、RD、BS 的值变化。
   练习：步骤排序；指出某一步的执行者；判断四个响应条件是否满足。
3. **三种集中式仲裁的动画**
   困惑："链式查询为什么离仲裁器近的优先？计数器从 0 计和从中止点计差在哪？"
   模型：同一组设备和请求，在三种方式下逐步播放 BR、BG、BS 或计数值；可切换计数起点；可断开链上某个接口看后果。
   练习：给定请求集合判断谁获得总线；按响应时间、线数、故障敏感度连线配对。
4. **同步、异步、半同步时序单步**
   困惑："异步读里的'确认'在等谁，撤销的顺序为什么不能乱？"
   模型：图 6.12、6.13、6.15 的波形逐事件点亮，旁边显示"谁做了什么、因为什么"；半同步可调从方速度，观察插入几个 Tw。
   练习：给跳变排因果顺序；看图判断定时方式；例 6.3 的七步标号。
5. **总线带宽与串行帧**
   困惑："一帧到底几位？带宽里的 M 是多少？"
   模型：帧构造器（起始、数据位数、校验、停止位）即时算波特率、字符速率和每位时间；字符波形绘制器，低位先发。带宽计算器可调每周期字节数、频率、每个总线周期的时钟数。
   练习：例 6.1、例 6.2、习题 10、习题 19 的同型换数题；画指定字符的波形。
6. **DMA 传送全过程**
   困惑："DMA 请求和中断请求有什么不同，什么时候响应，CPU 这时在干什么？"
   模型：图 8.16 控制器框图与图 8.17 流程联动，显示 HOLD、HLDA、地址计数器、字计数器；三阶段分段播放。字计数器提供"补码加 1 到溢出"和"减 1 到 0"两种显示，并说明教材两处写法不同。
   练习：三阶段的工作归类；指出哪些由 CPU 执行指令完成。
7. **三种 DMA 传送方式的时间图**
   困惑："周期挪用和透明 DMA 都没让 CPU 停下来，区别是什么？"
   模型：图 8.15 三条时间线，可调设备请求间隔与内存周期，显示 CPU 被占用的周期数。页面同时列教材名称和旧称。
   练习：给场景选方式；判断某周期总线归谁。
8. **多路型 DMA 时空图**
   困惑："两个设备同时请求先服务谁，会不会来不及？"
   模型：例 8.4 的可调版本，输入各设备间隔、服务时间和优先权，自动生成服务方块序列与空闲比例。
   练习：习题 15 的同型题；数某段时间内各设备的服务次数。
9. **二维多级中断的 IM 状态**
   困惑："执行 B 的服务程序时为什么是 111，执行 D 时为什么是 011？"
   模型：图 8.12(b) 的九设备阵列，点选正在服务的设备，显示 IM2 IM1 IM0 以及哪些设备此刻能打断它。
   练习：例 8.2 和习题 6、11 的同型题；"让某设备最优先"的调整题。
10. **中断饱和时间计算器**
    困惑："链上每个设备多等多少，极限频率怎么来的？"
    模型：例 8.3 的时间条，逐个设备堆叠 2TM、链延迟、TS、服务、TR。
    练习：习题 7 的同型换数题；习题 3 的采样系统题。
11. **程序查询与轮询流程**
    困惑："CPU 在查询循环里浪费了什么？"
    模型：图 8.3 的 ①–⑥ 单步，加图 8.4 的四设备轮询，可切换"服务后回主程序"与"服务后继续往后查"。
    练习：流程排序；指出改进前哪台设备会饿死。
12. **I/O 瓶颈与 DMA 开销**
    困惑："系统里到底谁拖后腿？"
    模型：例 8.5 的分步计算表，加 DMA 辅助开销比率计算（解析第25题型）。
    练习：换参数重算瓶颈、磁盘数、控制器数。
