# 开发计划

2026-11-14。计算机组成原理复习网站，面向上海师范大学本科生。

## 依据

- 教材：戴志涛、白中英《计算机组成原理》第七版（科学出版社，2024），配套《试题解析》第七版。
- 课程范围：第 1–6 章、第 8 章（第 7 章不讲）。
- 分章梳理：`docs/textbook/ch01-02.md`、`ch03.md`、`ch04-05.md`、`ch06-08.md`、`exam-types.md`。记号、算法步骤、题型都以这几份为准。
- 《全球教学资源调研与设计建议》只作参考。

## 负责人定下的要求

按重要性排列，原话在括号里。

1. 交互做到最好（「最重要的就是交互必须做的非常好」）。
2. 学生能理解（「必须让学生理解」「易懂」）。
3. 动画精美、有趣、好玩（「我希望动画做得非常精美」）。
4. 交互和答题都在 3D 场景里完成（「交互的时候答题的时候还是在 3D 场景内」）。
5. 没有 AI 味。
6. 范围和讲法跟教材走；设计建议文档只作参考。

## 教材决定的事

这本书和 RISC-V 路线的课程差别很大，下面几条直接决定做什么、不做什么。

| 主题 | 教材的讲法 | 网站的做法 |
|---|---|---|
| 溢出 | 变形补码，V=S_f1⊕S_f2 或 V=C_f⊕C_0 | 双符号位竖式为主 |
| 乘法 | 位积矩阵、阵列乘法器、算前算后求补；没有 Booth，没有移位相加 | 不做 Booth |
| 除法 | 原码加减交替法、CAS 阵列除法器，操作数是定点小数 | 按例 2.25 的表格版式 |
| 定点数 | 正文用定点整数，除法和解析书用定点小数 | 两种写法可切换 |
| 浮点 | IEEE 754，另有「阶码 3 位、尾数 6 位」的教学格式；0 舍 1 入 | 格式可配置 |
| cache | 按字编址，字段叫标记、行或组号、字地址；没有有效位，没有缺失分类；e=t_c/t_a | 用教材字段名，逐次访问的例子自己出 |
| 虚存 | 「a 进 c 出」列表法，FIFO 和 FIFO+LRU，指标是命中率 | 表格按列推进 |
| CPU | 图 5.1 模型机：多周期、以总线为中心，指存和数存分开，AR、DR，R0–R3，CPU 周期含 T1–T4 | 不做单周期 RISC-V 数据通路 |
| 控制器 | 微程序和硬布线都要会设计 | 课程重心，页面最多 |
| 流水线 | 先四段后五段，时空图、T_k、T_p、C_k；RAW、WAR、WAW；写回后下一周期才能读 | 按教材口径算停顿 |
| 汇编 | 32 位 ARM | 不讲 RISC-V |
| 中断、DMA | IM=1 关中断，屏蔽位 1 表示屏蔽；DMA 三种方式叫成组连续传送、周期挪用、透明 DMA | 用第七版名称，旁注旧称 |

解析书有若干答案有误（`ch01-02.md` 末尾列了几处）。网站的答案全部由程序算出，不抄书。

## 一页讲一个困惑

每页的标题是学生会问的一句话，例如「LAD 为什么比 ADD 多一个 CPU 周期」。页面由三部分组成，共用同一份状态记录。

- 讲解：一道完整的题，逐步推进。关键步骤先让学生预测，再给结果。
- 试一试：学生自己改输入、改参数，模型立刻重算。可以故意做错，看会出什么事。
- 练习：同题型换数的题，逐步判分，指出错在哪一步。最后一题不带动画。

每一步都显示三件事：现在的状态、这一步为什么能发生、哪里变了（旧值和新值）。

### 场景

整站是同一个 3D 实验台。每页是台面上的一套教具：寄存器、总线、三态门、存储阵列、位片、答题纸都是有体积的东西，学生的操作直接推动它们。规则写在 `docs/INTERACTION.md`。

- 答题就是在场景里动手：点选接收数据的寄存器，把值拖上总线，翻动位片，选主存块落到 cache 的哪一行。要填数的地方，输入框贴在对应部件旁边。
- 答错时场景按学生的答案演一遍再退回：两个三态门同时打开，两个值在总线上相撞。
- 纸面题是台面上的一张答题纸，按考试的版式填表，这一步不给动画。
- 文字、位串、表格始终正对屏幕。镜头只在焦点移出画面时移动，不旋转世界。手机上镜头跟着当前步骤走。
- 不支持 WebGL 或设备太旧时用平面模式，内容和答案相同。

### 好玩从哪来

动画画的是机制本身。

- 值是看得见的小牌，从打开的三态门滑上总线，走到接收的寄存器，旧值被顶出去。
- 进位跳到左边一列；双符号位变成 01 或 10 时溢出灯亮。
- cache 行被新块挤掉；页面在「a 进 c 出」表里像传送带一样下移，c 位置的页掉出去。
- 链式查询的总线授权沿着链往下传，被第一个请求的设备截住。
- 中断嵌套是一叠压住的程序，轨迹图随时间画出来。
- 每页有「弄坏它」的入口：选错屏蔽字看哪台设备饿死，把 T 调到大于 mτ 看交叉存储器冲突。
- 部分页面有挑战题：用最少的 CPU 周期完成一次传送，给一个访问序列把命中率做到指定值。

不做的：积分、徽章、连续打卡、吉祥物、与内容无关的装饰动画、霓虹和发光的机房风格。

### 三种页面形态

57 个页面归为三种形态，先各做一个样板，后面的页面照样板做。第一个样板是模型机指令周期，用它验证 3D 场景在手机上的清晰度和流畅度，再定其余页面的做法。

| 形态 | 场景里的样子 | 样板 |
|---|---|---|
| 结构型 | 部件立在台面上，值沿着连线移动 | 模型机指令周期 |
| 序列型 | 一串访问或事件依次作用在一组存储格或时间轴上 | cache 逐次访问与替换 |
| 算式型 | 位片排成竖式和运算表，进位和移位是位片的动作 | 变形补码加减与溢出 |

## 站点结构

- 首页：章节目录，上次学到哪一页。
- 学：左侧栏按章列出页面，当前页常亮，换页不跳动。
- 练：按题型出题，题型取自教材习题和解析书第 1–6、8、11 章的分类。
- 测：每章一组短题，做完列出错的题型和对应页面。
- 页面状态（第几步、参数、所选例题）全部写进网址，刷新和分享都回到同一个画面。
- 进度只存在学生自己的浏览器里。没有账号，没有后台，不收集数据。
- 手机可用：部件图在窄屏按步骤切局部，不缩成看不清的小图。
- 每页有可打印的步骤表。

## 技术方案

- Vite 8、TypeScript 7、Preact 11，纯静态站点。测试用 Vitest、fast-check、Playwright。
- `src/engines/<名>/`：每个主题一个引擎，纯函数，输入参数，输出状态序列（Trace）。不依赖界面。
- `src/scene/`：3D 部件库（three.js，按需加载）。部件的位置、颜色、文字只由 Trace 的状态决定。
- `src/player/`：统一的逐步播放器。上一步、下一步、重置、点选任一行、键盘操作、场景内答题、网址同步。
- `src/pages/<编号>/`：页面把引擎和部件接起来，不自己算答案。
- 场景、答题纸、提示、答案都读同一份 Trace，画面和文字不会对不上。
- 场景内的每个可操作部件都有对应的页面控件，键盘和读屏软件能用，自动检查也靠它。
- 随系统的「减少动态效果」设置，位移动画改为直接切换。
- 题目、解释、模型全部原创。教材只给页码指引，不搬原文和原题。

## 正确性怎么保证

| 对象 | 检查 |
|---|---|
| 引擎 | 小位宽穷举；fast-check 性质测试；与参考实现对拍（BigInt、DataView）；教材例题的数值作为固定用例 |
| Trace | 每步都有状态、理由、变化；变化等于前后状态之差；回退后状态与当初一致 |
| 页面 | Playwright：键盘操作、回退、网址还原、360 px 不横向滚动、触控目标 44 px、无控制台报错、减少动态效果 |
| 场景 | 每一步稳定后的场景状态与 Trace 一致；关键步骤截图比对；手机上转场不掉帧 |
| 动画 | 关键转场逐帧截图，对照 `docs/INTERACTION.md` 的动效标准审看 |
| 导航 | 侧栏位置和当前项检查（qa-navigation） |
| 文字 | no-ai-flavor 检查；教材术语表检查（例如写「修改位」不写「脏位」） |
| 原创 | 题目文字与教材、解析书的扫描文本比对，不许有长段重合 |
| 易懂 | 另开一个只看页面的审读 agent，照着步骤做变式题，卡在哪一步就改哪一步 |

真实学生的试用反馈比以上都重要。0.1 版上线后请几位同学各做一页，看他们卡在哪。
