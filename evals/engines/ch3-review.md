# 第 3 章六个引擎的参照测试审查

范围：`src/engines/{expand,decode,cacheaddr,cacheperf,vm,vmreplace}` 的 `reference.test.ts` 和 `golden.test.ts`，对照 `specs/3-expand.md`、`3-decode.md`、`3-cache-addr.md`、`3-cache-perf.md`、`3-vm-addr.md`、`3-vm-replace.md` 和 `docs/textbook/ch03.md`。版本 2832ba2，git 里没有改之前的版本，只按内容判断。
测试：`pnpm -s exec vitest run src/engines/expand src/engines/decode src/engines/cacheaddr src/engines/cacheperf src/engines/vm src/engines/vmreplace`：12 个文件、217 条，全部通过。
引擎行为另用 scratchpad 里的临时测试探过（不在仓库里），下文写「探针」。

## 问题（按严重程度）

- 中｜src/engines/decode/reference.test.ts:369-373｜`locate` 只查返回值里有没有组名，不查片内地址；区域外的地址也只查「没提到其他带编号的组」，不查是不是「没有芯片」（组名不带编号时，说错组也能通过）。性质 1 退化成 golden 里的 3 个例子｜依据：规格要求 11「locate 必须与 probe 步给出相同的芯片组和片内地址」、性质 1「片内地址 = (地址 − 组首地址)。区域外的地址 locate 返回没有芯片」。探针：`locate` 返回 `{chip, output, inner}`，E805H → inner 5，0005H → chip null，引擎目前是对的，把断言改成和 `refLocate` 逐项比较不会失败。
- 中｜src/engines/expand/reference.test.ts:257-262（对应 model.ts:368）｜注释说「只有 1 组时问不问没说」，只在组数 > 1 时查「选中第几组」。规格写的是给了 probe 就问，没有组数条件。测试放宽到和引擎一致，掩盖了引擎与规格的分歧｜依据：规格要求 10「给了 probe 时查地址步问「选中第几组」（数字）」。探针：1M×4 → 1M×8、probe 5，查地址步没有 ask。处理：改规格（只有一组时问第几组没有意义，写明不问），或者让引擎补上这道题；二者择一，不该只放宽测试。
- 低｜src/engines/expand/reference.test.ts:253-254｜注释说「规格不清」，把错误选项放宽成「任一全落在片内位里的选项」，也不查选项个数和去重｜依据：规格要求 10 写明选项是「正确答案、片内地址线 A(k−1)–A0、全部地址线 A(n−1)–A0，去重」，并不含糊。探针：4096×8 / 2048×8 时选项是 `A11`、`A10–A0`、`A11–A0`，满足严格写法，收紧不会失败。
- 低｜src/engines/decode/reference.test.ts:323-327｜门电路只查有没有「与门」「与非门」，不查哪几根地址线进与非门、哪几根要先经非门。只有场景（:437-438）查了 A12、A11，而那一例两根线都是 1，「取值为 0 的线先经非门」这一支没有任何测试｜依据：规格要求 5 第 3 条。探针：E800H–EFFFH 用 2K×16 位，引擎给「Y7 经非门，与 A12 经非门、A11 进与非门」；手算 E800H = 1110 1000 0000 0000，A12 = 0、A11 = 1，结果对。
- 低｜src/engines/decode/reference.test.ts（全文）｜要求 4 的使能端接法（恒 1 的线接 G1、恒 0 的线接 /G2B、各最多一根、74139 放不下多余的线）没有断言；arbSpec 生成了多余 1、2 根线的情形（:174-177），却不查 `enables`。golden 只有「G2B ← A15」和全默认，没有「G1 ← Ax」｜依据：规格要求 4。探针：只有 8000H–8FFFH 时得到「G1 ← A15」，A16、A15 都恒为 1 时报错，指定 74139 而 h = 4 时报错，引擎都对；缺的是测试。
- 低｜src/engines/decode/reference.test.ts:293-297｜查地址步的预测题只在命中时查答案里有组名，不查题型，也不查区域外答「没有芯片」｜依据：规格要求 11。探针：引擎出的是选择题，选项是各组名加「没有芯片」，区域外答「没有芯片」，都对。
- 低｜src/engines/vmreplace/reference.test.ts:225-226｜第 225 行注释说「命中」行第一格写「命中」，断言却是空串，行尾又注「例 3.11 这一行没有行名」，可见断言改过。断言本身对：ch03.md 第 270 行（第四行在命中的列写「命中」）、第 283、287 行自拟表的首格为空，evals/golden/vm-replace.json 的例 3.11 表也是空串。只是第 225 行注释过时，应删除。
- 低｜src/engines/cacheperf/reference.test.ts:71-77｜时间和周期数分支算出了 `approx`，却没断言不带「≈」，容差 0.05；h、r、e、CPI 分支都有这条断言｜依据：规格要求 7「result 和解题表只写数值」。另外 :323 的 `.replace('≈', '')` 比较宽，但 e 已由 `checkShown` 查过，没有实害。
- 低｜src/engines/cacheperf/reference.test.ts:284-286｜注释说规格只写了「l2Ns ≤ memoryNs 时」，现行规格性质 4 已经改成「l1Miss × l2Ns ≤ (l1Miss − l2Miss) × memoryNs」，断言与现行规格一致。手推：两级 CPI − 一级 CPI = l1Miss·L2 − (l1Miss − l2Miss)·M，条件成立时 ≤ 0。属于「规格后来澄清」，修改合理，只是注释过时。
- 低｜src/engines/vm/reference.test.ts:196-226｜不查每个地址的步数和顺序（切分 → 查快表 → 查页表 → access），「快表命中时不出现查页表的步」只用 access 步状态里 `valid` 为 null 来代替｜依据：规格要求 1、场景 4。golden.test.ts:37-41 有一例 `steps.length` 为 3；探针：快表未命中、缺页时是 切分 → 快表 → 页表 → access 四步，顺序对。
- 低｜src/engines/cacheaddr/reference.test.ts:250-255、348-350｜给 `fields` 时不查步数（规格要求 2：第一步写给定格式，再加 3 步切分）；组相联时不查 `r` 为 null。golden 的例 3.6 已经钉住 `r: null`。
- 低｜src/engines/expand/reference.test.ts:432-439，decode/reference.test.ts:444-467｜非法参数只测了场景里的两类。expand 的「组数 ≤ 16、每组片数 ≤ 16、位数 1–64、目标 ≤ 2^30、d ≥ 2」，decode 的「h < 2、多余的线超过 2 根」都没有测。探针：decode 这两种情况引擎都会报错。属于覆盖缺口，不是放松。

## 核对过、没有问题的断言

- vm/reference.test.ts:92-93：`pg`、`fr` 上限改成 min(20, 32 − off)，保证虚地址、物理地址都不超过 32 位，与规格参数表一致。这就是说的那个测试 bug，修改合理。
- cacheperf 参照：正向先用式(3.5) 求 t_a，再算 e = t_c/t_a，不走引擎的 1/[r+(1−r)h]，推导独立；对拍容差 1e-9（相对）；性质 1 的容差是规格写的 1e-9；4 位小数的容差 5e-5，e 的容差 0.05%，都和显示规则相符。由e求h 给了 r 时 result 只有 h，与要求 6「给定的量只列在条件里」一致。
- cacheperf 场景和 golden，手算：例 3.4 h = 0.95、r = 5、e = 50/60 = 83.3%、t_a = 60 ns；习题 9 h = 2420/2500 = 0.968，t_a = 0.968×40 + 0.032×240 = 46.4 ns，e = 40/46.4 = 86.2%；习题 10 h = (200−50)/(200−40) = 0.9375，e = 80%；例 3.8 损失 100/0.2 = 500，一级 CPI = 1 + 0.02×500 = 11，二级损失 25，两级 CPI = 1 + 0.02×25 + 0.005×500 = 4，性能比 2.75；自拟 4750/250/20/120 得 r = 6、e = 80%、t_a = 25 ns。
- cacheaddr 场景和 golden，手算：BBBBBB 切 8|14|2 得 10111011 | 10111011101110 | 11 = BBH、2EEEH、3H；例 3.6 得 w = 7、d = 4、u = 16、s = 12、标记 8、19 位；B0010 全相联得标记 B001H、字地址 0H；习题 15 得 w = 2、r = 14、s = 22、标记 8；A3C6 直接映射 101000|11110001|10 = 28H、F1H，2 路 1010001|1110001|10 = 51H、71H。参照用除法和取余，与二进制切分互相印证（性质 2、3）；性质 4 三种映射标记位数的大小关系成立。
- expand 场景和 golden，手算：2048K/256K = 8 组，n = 21，k = 18，A20–A18，第 7 组 7×40000H = 1C0000H 到 1FFFFFH；32K×16 / 8K×8 = 8 片 4 组，A14、A13，probe 4005H 在第 2 组、片内 5；1M×4 → 1M×8 得 D7–D4、D3–D0。性质 1–4 用参照（逐段累加，不做除法）对拍。
- decode 场景和 golden：习题 7 RAM 40K 用 8K×8 位共 10 片，A15–A13，Y0、Y1 经与门接 ROM，Y2 空，Y3–Y7 接 RAM1–RAM5；最高 2K（F800H，A12 = A11 = 1）经 Y7、非门、与非门；重叠和 A15 取值不同都报错。参照的组命名（同类按地址排序、只有一组不带编号）与要求 8 一致。
- vm 场景和 golden，手算：0DB4H → 页 3、1B4H → 5×400H + 1B4H = 15B4H；0AC5H → 页 2 → 4×400H + 2C5H = 12C5H；1AC5H → 页 6 未列出 → 缺页；8644 = 2×4096 + 452 → 8×4096 + 452 = 33220；0A2CH → 页 2 → 3×400H + 22CH = 0E2CH。性质 1–3 和参照（除法取余）对拍都在。
- vmreplace 场景和 golden，手算：例 3.11 FIFO 命中第 5、11 列，淘汰 0、1、2、4、3、0；FIFO+LRU 命中第 5、8、11 列，第 5 列 [2, 4, 1]；分析题 28 页号 1 2 1 0 4 1 3 4 2 1，FIFO 缺页 5 次、淘汰 0、1、2，LRU 缺页 6 次、淘汰 2、0、1、3；习题 19 LRU 缺页 6 次、淘汰 7、8；分析题 23 页面数为 3 时命中 2 次。参照不挪格子，按调入时刻或最近访问时刻排序，与引擎的下移写法独立；性质 1–3、带圈数字、命中率写法都按规格查。
- 六个引擎的规格场景在参照测试里一条不少；规格性质除 decode 性质 1 的片内地址部分（见上）外都有对应的性质测试。
