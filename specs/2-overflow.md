# 2-overflow：位运算库与变形补码加减引擎

困惑：01 和 10 哪个是正溢，进位丢掉算不算溢出。学完能用变形补码算 x+y、x−y，说出有没有溢出、是哪一种。
教材依据：2.1.1–2.1.2（p23–27，式 2.5–2.9）、2.2.1–2.2.3（p34–38，式 2.14–2.18）；求补的另一种做法 p46；加法器的溢出逻辑 p39 图 2.3(b)。
代码：`src/lib/bits.ts`；`src/engines/overflow/model.ts`，入口 `run(params)`，另有 `solve(params)`（只要答案）和 `operandFromUnits`。

## 参数

| 名 | 取值 | 说明 |
|---|---|---|
| `n` | 1–48 的整数 | 数值位数，不含符号位 |
| `op` | `加` `减` | |
| `notation` | `整数` `小数` | 只影响显示：小数点、真值写法、模写成 2^(n+2) 还是 4 |
| `x`、`y` | `{ as: '真值', text }` 或 `{ as: '机器数', bits }` | 真值是带符号的二进制数（+1010、-0.0111、-1）；机器数是 n+1 位补码或 n+2 位变形补码，定点小数可带小数点 |

## 要求：位运算库

1. 位串必须是只含 0 和 1 的定宽字符串，左边是高位；宽度不符、含别的字符必须抛 `BitsError`，不截断、不补位。
2. 真值必须统一用「以最低位为单位的整数」表示：定点整数就是它本身，定点小数是它乘 2^-n。编码、解码不分写法（p23）。
3. 必须能编码、解码原码、反码、补码、移码（宽 n+1 位）。范围：原码、反码 ±(2^n − 1)，补码、移码 −2^n 到 2^n − 1；超出范围必须抛 `BitsError`，信息里写明范围（p24–27）。
4. 原码、反码的 0 必须有两种形式（可指定编成负零），解码都得 0；补码、移码只有一种（p25）。
5. 移码必须按 [e]移 = 2^n + e（式 2.9，p27），与补码只差符号位。IEEE 754 的偏移 127 不许进这个文件。
6. 变形补码必须宽 n+2 位、模 2^(n+2)，操作数的两个符号位相同；解码按整串补码读，符号位 01、10 时读出的是超出范围的数学结果（p37–38）。
7. 由 [y]补 求 [−y]补 必须提供两种做法：连同符号位各位取反、末位加 1（式 2.16，p36）；从右往左找到第一个 1，它和右边不变、左边取反（p46）。
8. 行波相加必须返回和、每一位送出的进位、最高位向外的进位，支持进位输入（p39）。
9. 必须有两种写法的排版和读入：机器码 01001 / 0.1001 / 11.10001，真值 +1010 / −0.0111，十进制值精确不舍入。

## 要求：引擎

10. 状态必须是纯数据：`rows.x`、`rows.y`、`rows.inverted`、`rows.negY`、`rows.carry`、`rows.sum`（各有 `label` 和 n+3 格的 `cells`，加法时 `inverted`、`negY` 为 null），`dropped`，`sf1`、`sf2`，`cf`、`c0`，`vBySign`、`vByCarry`，`verdict`，`value`，`conclusion`。没写的格是空串。
11. 每行第 0 格是最高符号位左边的出界格，第 1、2 格是 S_f1、S_f2，其后是数值位。进位行第 c 格必须是进入第 c 列的进位，第 0 格是向外的进位。
12. 步骤必须按这个顺序：写 [x]变补；写 [y]变补；减法再加两步，[y]变补 各位取反、末位加 1 得 [−y]变补（式 2.15、2.16，p36）；从最低位起一列一步相加，共 n+2 步，层级 `beat`，每步写一位和、一位进位，两个符号位照样相加（p38）；丢掉最高符号位向外的进位（p38）；读两个符号位，按 V = S_f1 ⊕ S_f2 判定；用 V = C_f ⊕ C_0 再判一次；结论。其余步的层级是 `explain`。
13. 每一步必须有 `title`、`why`、`ref`（教材页码）。丢进位那一步的 `why` 必须说明原因是按模运算，并说明丢进位不等于溢出。
14. 符号位 00、11 必须判无溢出，01 正溢，10 负溢；最高符号位是结果的真实符号（p38）。
15. C_0 必须是最高数值位送进符号位的进位，C_f 是符号位再向左的进位，取自进位行第 2、第 1 格（p38）。
16. 减法且 y 是最小负数时，[−y]变补 的符号位是 01，必须照常相加并以两个符号位的结论为准；这时 C_f、C_0 必须按加法器重算：[x]补 加 [y]补 各位取反，最低位进 1（p39 图 2.3(b)），不取进位行。
17. 结论必须是：无溢出时给出真值和十进制值；正溢、负溢时给出数学上的结果和它超出的上限或下限。
18. 预测题必须只有两道，答案取自引擎：第二符号位那一列之前问「结果的两个符号位」（`bits`）；判定那一步之前问属于哪一种（`choice`：无溢出、正溢、负溢）。
19. `table` 必须是纸面竖式，一位一列，列头是 出界、S_f1、S_f2 和各数值位的权，定点小数多一列小数点。行：进位、[x]变补、+ [y]变补 或 + [−y]变补、结果；减法在前面多 [y]变补、各位取反 两行。每行指回写出它的那一步。
20. `result` 必须有 `结果的变形补码`、`是否溢出`；无溢出时再有 `真值`。
21. 文字必须用教材的说法：变形补码、符号位、数值位、正溢、负溢、模。不写教材原句。
22. 参数不合格必须抛 `BitsError`，说明原因：真值超出 −2^n 到 2^n − 1、机器数位数不对、变形补码两个符号位不同、定点整数带小数点、`op` 或 `notation` 不认识。

## 场景

- WHEN n=4、整数、x=+1010、y=+0111、加 THEN 竖式 001010 + 000111 = 010001，没有进位丢掉，符号位 01，正溢，`result` 没有 `真值`。
- WHEN x=+1011、y=−0101、加 THEN 最高符号位向外进 1 并丢掉，符号位 00，无溢出，真值 +0110。
- WHEN x=−1100、y=−1000、加 THEN 符号位 10，负溢，C_f=1、C_0=0。
- WHEN x=+1101、y=+0110、减 THEN 多出取反、加 1 两步，[−y]变补 = 111010，结果 000111，真值 +0111。
- WHEN n=5、小数、x=−0.01111、y=+0.11001、减 THEN 各处带小数点，结果 10.11000，负溢，模写作 4。
- WHEN [x]补=11111、[y]补=10000、n=4、减 THEN [−y]变补 = 010000，结果 001111，无溢出；C_f=C_0=1 来自加法器的算法，这一步不高亮进位行。
- WHEN x=+10000、n=4 THEN `run` 抛出错误，写明范围是 −10000 到 +1111。

## 性质

1. 对任意 x、y、n、`op`：`verdict` 与「x ± y 是否落在 −2^n 到 2^n − 1 之外」一致，`vBySign` = `vByCarry`。
2. 结果行按模 2^(n+2) 的补码读出总等于数学上的 x ± y，溢出时也是（式 2.18，p38）。
3. `dropped` 与 `verdict` 互相独立：有无进位、有无溢出的四种组合在加法和减法里都出现。
4. 两种写法的状态只差文字：竖式每一格、两个进位、判定都相同。
5. 取反加 1 与从右扫描对任意位串结果相同；同样的参数得到完全相同的 Trace，`validateTrace` 为空。

固定用例：`evals/golden/overflow-cases.json`，21 个，含例 2.13、2.15、2.18、2.19 的数值（p35–38）和解析 p14 计算 7、8(1)、9(1) 的数值。解析 9(1) 印的真值有误，用例里是算出来的 −0.1101。测试另有 `n` = 2…5 的全部 x、y、两种运算、两种写法与整数参照对拍，按运算和写法分成四个文件。
不做：操作数与结果符号位比较的判法（教材没有）、移码加减的溢出表（表 2.5，留给浮点页）、十进制真值输入、原码和反码的加减。

## 待确认

- 减去最小负数（要求 16）教材没有讲，现在的处理是照常算并改用加法器的进位。也可以改成拒绝这种输入。
- 教材的竖式不写进位行，只把丢掉的进位画在虚线框里（p35、p37）。进位行放在最上面、出界格放在最左，是本站定的版式。
- 符号位预测题放在加符号位之前，属于先猜再算；也可以挪到读符号位那一步，页面做出来后看学生的反应再定。
- 位下标有两套（x_n 为符号位，或 x_0 为符号位）。引擎不输出下标，列头用位权；页面要不要显示下标没定。
