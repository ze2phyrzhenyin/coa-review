# 5-stall 相关之后停几拍（引擎 `src/engines/pipeline/stall.ts`）

困惑：相关之后停几拍，定向以后呢。学完能按教材的口径排出不处理、后推、定向三种情况下每条指令在各个周期所在的段，数出总周期数。

教材依据：5.6.3，p189–191（资源相关表 5.3、数据相关表 5.4、后推法与定向技术）；习题 12，p202；解析书 析15（p82–83，表 5.4(a)(b)）。梳理见 `docs/textbook/ch04-05.md`「推迟多少拍」。

## 要求

1. 入口 `runStall(params)`；`schedule(params)` 只排时间；`generateStall(seed)` 出题。参数：`stages` 4 或 5，1–8 条指令（写法同 5-hazard），`mode` 不处理｜后推｜定向，可选 `sharedMemory`（只用于五段）、`dt`。
2. 四段 IF ID EX WB，五段 IF ID EX MEM WB（p190）。按序流动，每段每个周期至多一条，前一条没离开下一段时后一条停在原段。
3. 教材的口径：前一条写回寄存器之后的下一个周期才能读到（p202 习题 12、解析书 析15）。读寄存器发生在最后一个 ID 周期。
4. 后推：后一条停在 ID，直到最后一个 ID 周期不早于写回的下一个周期，后面的指令依次顺延。四段相邻相关停 2 拍，五段停 3 拍。
5. 定向：结果产生的下一个周期就能进 EX；五段里 LAD 的结果在 MEM 末尾产生，其余在 EX 末尾。四段定向不停顿。
6. 不处理：不停，列出读到旧值的指令和寄存器（读的周期不晚于写回周期）。
7. `sharedMemory`：LAD、STO 在 MEM 的那个周期，后面的指令不能取指，推迟一拍（表 5.3）。
8. 第一步 `explain` 说明处理方式；每个周期一步（`cycle`），`why` 写出谁在等、等谁的哪个寄存器、几号周期才拿得到；最后一步 `explain` 给出总周期数和比 k+(n−1) 多出的周期。
9. 状态：`cycle`、`grid[指令][周期]`、`stages`（每段里是哪条）、`waiting`、`wrong`、`total`。
10. `trace.table`：指令＼周期，进入某段的那一格写段名，等待的格写「停」，等完读寄存器的那一格再写一次 ID（照表 5.4(b)）；每行指回该指令取指的周期步。
11. `result`：总周期数、无相关时、多用的周期；不处理时加「读错」；给了 dt 加「用时」。
12. 预测题：第一次因数据停顿时问在 ID 多等几个周期；最后问总周期数。

## 场景

- WHEN 析15 的五条指令、五段、后推 THEN 12 个周期，表格同表 5.4(b)。
- WHEN 同一组、不处理 THEN 9 个周期，I2、I3、I4 读错 R2。
- WHEN 四段、相邻 RAW、后推 THEN 7 个周期，停 2 拍；定向 THEN 5 个周期。
- WHEN 五段、`LAD R1,M(y)` 后紧跟 `ADD R2,R1,R3`、定向 THEN 7 个周期。
- WHEN 单端口存储器、I1 是 LAD THEN I4 在第 5 个周期才取指。

## 性质

1. 各指令进入各段的周期、总周期、读错与逐拍模拟的参照一致。
2. 不争用存储器时：不处理 = k+n−1 ≤ 定向 ≤ 后推。
3. 后推时读寄存器的周期总在最近一次写回之后；指令按序进入每一段。
4. `validateTrace` 为空；同参数同 Trace；每个周期每段至多一条在做事的指令。

## 固定用例

`evals/golden/pipeline-stall.json`：析15 三种方式、习题 12 两种方式、表 5.3 的资源相关、一个 LAD 定向的自出例子。

## 不做

控制相关（冻结、延迟转移、转移预测只讲概念）、超标量、前半周期写后半周期读的口径、编译器插空操作。
