# 2-fpadd：浮点加减引擎

困惑：对阶移谁，规格化往哪边移。学完能按教材的几步算出两个浮点数的和、差：0 操作数检查、对阶、尾数加减、规格化、舍入、溢出判断，每步说出阶码和尾数怎么变。
教材依据：2.6.1（p62–65，式 2.35，图 2.17 流程，对阶 p63，规格化、舍入、溢出 p64）；例 2.30（p65–66）；0 舍 1 入 p67；习题 9（p69）。解析计算 17、28、29（解析 p17–21）。
代码：`src/engines/fpadd/model.ts`，入口 `run(params)`，出题 `generate(seed)`。

## 参数

两种格式，用 `style` 区分。

| 名 | 取值 | 说明 |
|---|---|---|
| `style` | `补码` | 习题 9 的教学格式：阶码 k 位数值位、用补码，尾数 m 位数值位、用变形补码，运算时阶码也写两个符号位 |
| `k`、`m` | 2–4、3–12 | 阶码、尾数的数值位数 |
| `x`、`y` | `{ exp, mant }`：阶码真值（二进制，如 −011）和尾数真值（如 −0.011110） | 操作数可以不是规格化数 |
| `style` | `有效位` | 例 2.30 的写法：(1.xxx)₂ × 2^e，符号单独写，e 的范围 −126 到 127 |
| `digits` | 2–12 | 有效位数，含小数点前的 1 |
| `x`、`y` | 十进制（0.5、−0.4375、3/8） | 必须能用 `digits` 位有效位精确写出 |
| `op` | `加` `减` | |
| `rounding` | `0舍1入` `截断`；`有效位` 另有 `就近舍入` | |

## 要求

1. 状态必须是纯数据：`x`、`y`（各有 `exp` 阶码真值、`expCode` 阶码的变形补码（`有效位` 格式为空串）、`mant` 尾数的机器写法、`out` 右移出去的位），`check`（0 操作数检查的结论），`diff`、`diffCode`（阶差 ΔE 和它的码，未求为空串），`shift`（被移的是 `x`、`y` 还是「不移」），`sum`（`exp`、`expCode`、`mant`、`out`），`norm`（规格化方向），`stage`（当前阶段名），`overflow`（`''`、`无溢出`、`上溢`、`下溢`），`result`（结果写法）、`decimal`（结果的十进制值）。
2. 步骤必须按这个顺序：写出两数的阶码和尾数；减法把 y 的尾数变符号（`补码` 格式是求 [−My]补）；0 操作数检查（有 0 就直接得出结果并结束，图 2.17）；求阶差；对阶，小阶加 1、尾数右移 1 位，一位一步；尾数加减；规格化，一位一步；舍入；溢出判断。层级都是 `explain`。
3. 对阶必须是小阶向大阶看齐（p63）：阶码小的那个数的尾数右移，阶码加 1，直到两阶相等；`补码` 格式右移时符号位复制。右移出去的位必须留在 `out` 里，表上写在括号中，到舍入时才处理（p64）。对阶时尾数的 m 位全部移成 0 时，结果直接取另一数（图 2.17）。
4. 尾数加减：`补码` 格式两个变形补码连同括号里的位一起相加，丢掉最高符号位的进位；`有效位` 格式按带符号的二进制数相加。结果尾数为 0 时结果为 0。
5. 规格化：`补码` 格式两个符号位是 01、10 时向右规格化一位、阶码加 1；是 00.0、11.1 开头时向左规格化，每次左移一位、阶码减 1，括号里的位跟着左移（p64；补码尾数规格化的条件见待确认）。`有效位` 格式大于等于 2 右移，小于 1 左移，直到 1.xxx。
6. 舍入：`0舍1入` 看被舍去的最高位，是 1 就在尾数最低位加 1（p67）；`截断` 直接丢掉；`就近舍入` 按 p64。舍入后尾数溢出时必须再向右规格化一次。
7. 溢出判断：`补码` 格式看阶码的两个符号位，01 上溢、10 下溢，下溢结果为 0（p64）；规格化中阶码一越界就停下，不再舍入，直接判溢出（图 2.17）；`有效位` 格式看 127 ≥ e ≥ −126（例 2.30）。`有效位` 格式按例 2.30 的顺序先查溢出再舍入。
8. 预测题只有两道，答案取自状态：求出阶差后问「哪个数的尾数右移」（`choice`：x 的尾数、y 的尾数、都不移）；规格化之前问「往哪边规格化」（`choice`：向左规格化、向右规格化、不用规格化）。
9. `table` 必须是纸面写法，列为 步骤、阶码、尾数、说明：[x]浮、[y]浮（减法多一行 [−y]）、对阶后、尾数相加（竖式三行）、规格化后、舍入后、结果；每行指回一步。括号里的位照写。
10. `result` 必须有 `结果`（`补码` 格式写 2^阶码 × 尾数真值，`有效位` 格式写 ±(1.xxx)₂ × 2^e）、`阶码`、`尾数`、`溢出`、`十进制`。
11. `generate(seed)` 必须是纯函数，题目里阶差不为 0 的占多数，规格化向左、向右、不用三种都会出现。
12. 参数不合格必须抛错并说明：k、m、digits 超出范围；阶码或尾数真值写不下；`有效位` 的十进制数用 `digits` 位写不出来。

## 场景

- WHEN `有效位`、digits=4、x=0.5、y=−0.4375、加 THEN y 的尾数右移 1 位成 −(0.111)₂ × 2^-1，和为 (0.001)₂ × 2^-1，向左规格化 3 位得 (1.000)₂ × 2^-4，无溢出，十进制 0.0625（例 2.30）。
- WHEN `补码`、k=3、m=6、x = 2^-101 × (−0.010110)、y = 2^-100 × 0.010110、加 THEN x 的尾数右移 1 位成 11.110101(0)，和 00.001011(0)，向左规格化 2 位得 2^-110 × 0.101100（解析计算 28 的数值；解析印的符号有误）。
- 同一组数做减法 THEN 和 11.011111(0)，已是规格化数，结果 2^-100 × (−0.100001)。
- WHEN `补码`、k=3、m=6、x = 2^-011 × 0.100101、y = 2^-010 × (−0.011110)、减 THEN 对阶后 00.010010(1)，和 00.110000(1)，0 舍 1 入后 00.110001。
- WHEN x 为 0 THEN 0 操作数检查之后直接得到 ±y，没有对阶的步。
- WHEN 两个最大正数相加 THEN 向右规格化后阶码符号位 01，上溢。

## 性质

1. 不舍入、不溢出时，结果的值等于 x ± y 的精确值；舍入时误差小于结果尾数最低位的权（0 舍 1 入不超过半个）。
2. 结果除 0 外总是规格化的；阶码等于大阶减去左规次数加上右规次数。
3. 对阶右移的次数等于 |ΔE|，被移的总是阶码小的那个数。
4. x 加 y 与 y 加 x 结果相同；x 减 y 与 x 加 (−y) 结果相同。
5. 同样的参数得到同样的 Trace，`validateTrace` 为空。

固定用例：`evals/golden/fpadd-cases.json`，含例 2.30、习题 9 两小题的加减（手算，解析计算 28 的数与习题 9(2) 相同）。
不做：移码阶码的加减和表 2.5（留给 2-fpmul）、原码尾数的加减（解析计算 29）、浮点乘除、IEEE754 位串上的加减、流水线。

## 待确认

- 补码尾数的规格化用解析书的规则（符号位与最高数值位不同），11.100…0 还要左移。教材正文只写了原码和 IEEE754。
- 补码尾数的 0 舍 1 入直接对补码位串做（舍去的最高位是 1 就在末位加 1）。教材只给了原码的规则。
- 溢出判断放在舍入之后（2.6.1 的顺序）；`有效位` 格式按例 2.30 放在舍入之前。
