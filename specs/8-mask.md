# 8-mask：多级中断屏蔽字与运行轨迹引擎

困惑：响应次序是硬件定死的，为什么改屏蔽字就能改处理次序。学完能由处理次序填屏蔽字表，由屏蔽字表反推处理次序，按请求到达时刻画出 CPU 运行轨迹。
教材依据：多级中断的规则（p270：本级和更低级置 1 关闭，更高级清 0 开放；屏蔽寄存器内容是现场，用堆栈保存）；图 8.12(a) 的嵌套示意；图 8.13 请求与屏蔽相与后排队（p272）；习题 8（p290，1 = 屏蔽）。
教材正文没有屏蔽字的例题，也没有运行轨迹的画法；能依据的只有 p270 的规则和习题 8。本引擎的做法是按规则推出的，页面要写明这一点。
代码：`src/engines/mask/model.ts`，入口 `run(params)`；另有 `validateParams`、`masksFromOrder(levels, order)`、`orderFromMasks(masks)`（排不出为 null）、`simulate(params)`（返回 `{ segments, done, end }`）、`generate(seed)`。

## 参数

| 名 | 取值 | 说明 |
|---|---|---|
| `levels` | 2–6 | 级 L0 … L(n−1) |
| `response` | 0…n−1 的排列，高到低 | 响应优先次序，缺省 L0 最高 |
| `order` | 0…n−1 的排列，先到后 | 要求的处理次序；与 `masks` 最多给一个 |
| `masks` | n 个长 n 的 0/1 串 | 第 i 个是 Li 处理程序的屏蔽字，左起依次是 L0…L(n−1) 位 |
| `arrivals` | 1–12 项 `{ level, at }` | 请求到达时刻，0–100 的整数 |
| `service` | 1–20 的整数，或每级一个 | 每级处理程序自身要运行的时间 |

## 要求

1. 屏蔽字的来历：给了 `order` 时，Li 的屏蔽字在自己和处理次序排在 Li 之后的级上为 1，其余为 0；给了 `masks` 就用它；都没给时按 p270，即 `order` 取 `response`。
2. 反推：每行 1 的个数各不相同且与 `masksFromOrder` 的结果一致时，按 1 的个数从多到少排出处理次序；否则说明「不能排成一个处理次序」，仍照屏蔽字仿真。
3. 主程序的屏蔽字全 0。CPU 在任一时刻：先结束剩余时间为 0 的处理程序（出栈，恢复被打断者和它的屏蔽字），再登记这一时刻到达的请求（请求寄存器该位置 1，已是 1 则合并），再看 请求 ∧ ¬屏蔽：不为 0 时由排队器按 `response` 选最高的一级，当前程序进栈，屏蔽寄存器换成该级的屏蔽字，该位请求清 0；重复直到没有可响应的请求。
4. 响应、返回不花时间；刚进入的处理程序可以立刻被它开放的级打断。时间只花在运行上。
5. 步序：先为每个处理程序写屏蔽字或数 1 的个数（`explain`，每级一步），给出处理次序；然后按事件推进：请求到达（`explain`）、响应进入某级（`cycle`）、运行一段（`instruction`）、处理完返回（`explain`）。
6. 状态必须是：`t`、`running`（级号，主程序为 −1）、`imr`（屏蔽寄存器，0/1 串）、`irr`（请求寄存器）、`stack`（`{ who, remaining, imr }`，栈顶在末尾）、`remaining`（当前程序还要运行多久，主程序为 null）、`masks`、`order`（反推不出为 null）、`segments`（`{ who, from, to, depth }`，depth 主程序为 0、每嵌套一层加 1；同一次进入的程序连续运行合成一段，被打断后接着运行、或同一级第二次进入都另起一段；零长度的段不记）、`done`（完成的级，按先后）。
7. 预测题：有两级以上请求在等、且响应结果与「谁的响应优先级最高」不同或进入的级会被立刻打断时，问「接下来 CPU 进入哪一级」；推屏蔽字时对第二个及以后的处理程序问屏蔽字（`bits`）。
8. `table` 是习题 8 的版式：中断处理程序 | L0 级 | … | L(n−1) 级，每行指回推这一行的步；反推时最后一列加「1 的个数」。
9. `result` 必须有 屏蔽字（按行用 / 隔开）、处理次序、完成次序、运行轨迹（每段「谁 起–止」用逗号隔开）、结束时刻。
10. 参数不合格时 `run` 抛出错误，原因与 `validateParams` 相同。

## 场景

- WHEN 5 级、响应 L0 最高、处理次序 L1→L3→L0→L4→L2 THEN 屏蔽字是 10101、11111、00100、10111、00101（按规则推，p290 的题型）。
- WHEN 同上、5 级都在 0 时刻请求、每级运行 2 THEN 完成次序 L1、L3、L0、L4、L2，结束时刻 10。
- WHEN 不给 `order` 和 `masks` THEN 处理次序就是响应次序，屏蔽字是上三角全 1。
- WHEN `masks` 的某行把自己置 0 而该级在处理中又来请求 THEN 自己打断自己，栈深加 1。

## 性质

1. 每个到达的请求（合并后）恰好完成一次；结束时栈空，回到主程序。
2. 每次进入某级时，该级在被它直接打断的那个程序的屏蔽字里为 0（嵌套合法）；栈深不超过请求次数。
3. 所有请求同时到达、屏蔽字由 `order` 推出时，完成次序等于 `order`。
4. `orderFromMasks(masksFromOrder(o))` = o；屏蔽字由次序推出时第 k 个处理的级那一行有 n−k+1 个 1。
5. 与独立写的逐单位时间推进的朴素参照一致（轨迹段、完成次序）；同样参数同样 Trace，`validateTrace` 为空。

固定用例：`evals/golden/mask-cases.json`。习题 8 的条件（p290）按规则推出的屏蔽字和同时请求时的轨迹；一个请求先后到达的手算例；一个缺省（处理次序 = 响应次序）的手算例。
不做：二维多级中断的级内链式查询（8-im）、屏蔽寄存器以外的现场时间、中断饱和时间。

## 待确认

- 响应和返回不占时间。画轨迹时各段首尾相接，实际机器上中间有中断周期和保存现场的时间。
- 同一级的请求在没被响应之前又来一次，只记一次。
- 「屏蔽字」是统考的叫法，教材叫中断屏蔽寄存器的内容或屏蔽位（p270、p290）；页面正文用教材叫法，括注屏蔽字。
