# 2-codes：原码、反码、补码、移码引擎

困惑：−128 为什么只有补码，补码和移码差在哪。学完能把一个真值写成四种机器码，说出每种码能表示的范围、0 有几种写法。
教材依据：2.1.2（p24–27，式 2.5–2.9）；原码→反码→补码的两步规则 p27；例 2.1–2.4（p26–27）、例 2.7–2.8（p29–30）；习题 1、2（p68）。
代码：`src/engines/codes/model.ts`，入口 `run(params)`；出题 `generate(seed)`；位运算全部用 `src/lib/bits.ts`。

## 参数

| 名 | 取值 | 说明 |
|---|---|---|
| `n` | 1–48 的整数 | 数值位数，不含符号位；机器码宽 n+1 位 |
| `notation` | `整数` `小数` | 定点整数或定点小数 |
| `input` | `{ as: '十进制', text }`、`{ as: '真值', text }`、`{ as: '机器数', code, bits }` | 十进制如 −35、0.375；二进制真值如 −0100011、−0.0111；机器数是 n+1 位的某一种码 |

## 要求

1. 状态必须是纯数据：`value`（`binary`、`decimal`）、`codes.原码`、`codes.反码`、`codes.补码`、`codes.移码`，每种码有 `bits`（不带点）、`text`（教材写法）、`zero`（0 的另一种写法，没有就是空串）、`status`（`''` 未写、`有`、`无`）、`why`（这种码为什么没有，只在 `无` 时有字）。
2. 步骤必须按这个顺序：读真值（输入是十进制时先化成二进制；输入是机器数时按该码的规则还原真值，补码用式 2.8）；原码；反码；补码；移码；核对补码和移码只差符号位。层级都是 `explain`。
3. 原码必须是符号位加 |x| 的 n 位数值位（式 2.5）；0 必须同时给出 +0、−0 两种形式（p25）。
4. 反码：正数与原码相同；负数必须由原码「符号位不变、数值位逐位取反」得到（p27）；0 有两种形式。
5. 补码：正数与原码相同；负数必须由反码「末位加 1」得到（p27），定点小数末位的权写 2^-n；x = −2^n（小数为 −1）时原码、反码写不下，补码必须按定义 2^(n+1) + x（小数 2 + x）直接写出 1000…0（式 2.6、2.7）。
6. 移码必须是 2^n + x（式 2.9），整数写成教材的逗号形式 1,0101；`why` 必须说明它与补码只差符号位。定点小数按 1 + x 计算（见待确认）。
7. 超出范围的码必须标 `无` 并说明：原码、反码只到 ±(2^n − 1)，补码、移码 −2^n 到 2^n − 1；输入超出全部四种码的范围必须抛错，写明范围。
8. 预测题最多三道，答案取自状态：负数时在反码、补码前各问一次位串（`bits`）；x = −2^n 时在原码前问「原码能不能表示」（`choice`），补码前照样问位串（题面改为按定义 2^(n+1) + x 写）；x = 0 时在补码前问「补码的 0 有几种写法」（`choice`）。三种情况都没有时在移码前问移码位串。
9. `table` 必须是例 2.3、2.4 那样一行一个量：真值（二进制）、[x]原、[x]反、[x]补、[x]移，列为 量、机器数、怎么得到；每行指回写出它的那一步；0 的两种写法写在同一格，用「或」隔开；写不下的写「无」。
10. `result` 必须有 `真值`、`[x]原`、`[x]反`、`[x]补`、`[x]移`；写不下的值为「无」。
11. `generate(seed)` 必须是纯函数，同一个种子同一组参数；约一成的题目落在 −2^n、0、±(2^n − 1)、−1 上。
12. 参数不合格必须抛 `BitsError`：n 不在 1–48、小数真值的位数超过 n、机器数位数不是 n+1、十进制小数在 n 位里写不下。

## 场景

- WHEN n=7、整数、十进制 −35 THEN 原码 10100011，反码 11011100，补码 11011101，移码 0,1011101。
- WHEN n=7、整数、十进制 −128 THEN 原码、反码为「无」，补码 10000000，移码 0,0000000，有一道「原码能不能表示」的预测题，答案「不能」。
- WHEN n=7、整数、十进制 0 THEN 原码 00000000 或 10000000，反码 00000000 或 11111111，补码只有 00000000。
- WHEN n=4、小数、真值 −0.0111 THEN 原码 1.0111，反码 1.1000，补码 1.1001。
- WHEN n=8、机器数 补码 110011011 THEN 真值 −101（例 2.2 的数值）。
- WHEN n=7、十进制 200 THEN 抛错，信息里有 −128 到 127。

## 性质

1. 四种码各自按定义解码都回到同一个真值（负零解为 0）。
2. 补码与移码只差最高位；正数的原码、反码、补码相同。
3. 负数（不是 −2^n）的补码等于反码加 1、反码等于原码数值位取反。
4. 码的有无与范围一致：x = −2^n 时只有补码、移码；同样的参数得到同样的 Trace，`validateTrace` 为空。
5. 输入为某种码的机器数时，得到的四种码与输入同一真值时完全相同。

固定用例：`evals/golden/codes-cases.json`，含例 2.3、2.4（±122）、例 2.1、2.2（9 位补码）、例 2.8 表的五个真值、p27 移码的 ±10101、习题 1 的四个数（手算）。
不做：十进制数串、BCD、校验码；变形补码（在 2-overflow）；码值大小比较题（页面用 result 自己比）。

## 待确认

- 教材的移码只对整数阶码定义（p27），定点小数的移码按 1 + x 算，写法同小数点形式。也可以对小数不给移码，要看任课老师的口径。
- 反码的步骤从原码取反得到，不另写解析书的小数公式 2 − 2^-n + x。
