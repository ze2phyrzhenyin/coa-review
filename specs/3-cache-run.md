# 3-cache-run：cache 逐次访问引擎

困惑：主存块落到哪一行，为什么被换出。学完能对一串地址填出命中/缺失表，求 h。
教材依据：3.6.1–3.6.4，p100–109，式(3.4)–(3.8)。教材没有访问序列的例题，例子都是本站自己出的。
代码：`src/engines/cache/model.ts`，入口 `run(params)`；另有 `validateParams`、`layout`、`splitAddress`、`performance`。

## 参数

| 名 | 取值 | 说明 |
|---|---|---|
| `mapping` | `全相联` `直接` `组相联` | p102–106 |
| `rows` | 2 的幂，不超过 256 | cache 行数 m = 2^r |
| `rowsPerSet` | 2 的幂，不超过 `rows` | 每组行数 v，只有组相联用；组数 u = m ÷ v = 2^d |
| `blockWords` | 2 的幂，不超过 1024 | 每块字数 k = 2^w |
| `addressBits` | 1–32 | 地址位数，按编址单位算；标记至少 1 位 |
| `unit`、`wordBytes` | `字`（缺省）或 `字节`；1、2、4、8（缺省 1） | 按字节编址时每块占 k × `wordBytes` 个地址，最低字段仍叫字地址（p108 例 3.7） |
| `replacement`、`seed` | `LFU` `LRU` `随机`；0 到 2^32−1 的整数 | 一个块有不止一行可放时必须给；`随机` 必须给种子 |
| `accesses` | 1–200 项 `{ address, op }`，`op` 为 `读` 或 `写` | 地址是十进制整数 |
| `tc`、`tm` | 正数，单位 ns，一起给 | 可选 |
| `validBit` | 布尔 | 只影响显示 |

## 要求

1. 状态必须是纯数据：`rows[i]` 有 `tag`、`block`、`modified`（修改位）、`count`（计数器）；空行的 `tag`、`block` 为 null。`access` 是当前访问的字段划分、候选行和结果；另有 `hits`、`misses`。
2. 地址必须切成 标记 | 行号或组号 | 字地址。块号 j = 地址 ÷ 每块地址数，取整。直接映射 i = j mod m（式 3.7，p103）；组相联 q = j mod u（式 3.8，p105），第 q 组是行 q·v 到 q·v+v−1；全相联的标记就是块号（p102）。
3. 每次访问必须恰好 5 步，顺序固定：切地址、定位行或组（写出求余算式）、比标记、命中或调入空行或替换、更新计数器和统计。前 4 步是 `explain`，第 5 步是 `access`。每步都有 `title`、`why`、`ref`。
4. 候选行里有空行时必须调入行号最小的空行，不替换；都占着才替换（p105、p108）。
5. LFU 必须：新调入的行计数器为 0；命中时该行加 1；替换时换出计数最小的行，并列取行号最小的；替换后候选各行计数器全部清零（p108）。
6. LRU 必须：命中的行清零，同组其余有块的行加 1；调入的行按刚用过处理；替换时换出计数最大的行（p108）。
7. 随机必须用 mulberry32(`seed`) 依次产生 32 位无符号数，每次替换取一个数 x，换出候选行里的第 x mod v 行；不用计数器（p109）。
8. 一个块只有一行可放时（直接映射，或 v = 1）必须直接换出该行，计数器保持 0（p108）。
9. 写必须按写回法：写命中、写缺失调入后修改位都置 1；调入新块时修改位先清 0；换出修改位为 1 的块时，`access.writeBack` 为真，解题表「换出」写「块 n（写回）」（p109）。
10. 预测题必须只有两种，答案取自引擎的结果。比标记步上的「这次访问命中吗」（命中 / 缺失）：块号与上一次访问不同，且这个块之前访问过或候选行已占满时才出。替换步上的「换出哪一行」（候选行名）：LRU，或计数不并列的 LFU，且候选不止一行时才出。
11. `table` 必须是 访问 | 块号 | 行号（组相联为组号，全相联为所在行）| 标记 | 结果 | 换出，每行指回这次访问的 `access` 步。
12. `result` 必须有 命中次数、缺失次数、h；给了时间再加 r = t_m/t_c、t_a = h·t_c + (1−h)·t_m、e = t_c/t_a（式 3.4–3.6，p101）。
13. `validBit` 为真时每行必须多一个 `valid`（空行 0，有块 1），其余输出不变；为假时状态和文字里都不出现有效位。
14. 文字必须用教材的说法：行、块、标记、行号、组号、字地址、修改位、命中、缺失。条件里同时列出图中的叫法 区号 | 区内块号 | 字地址（p104–107）。
15. 参数不合格时 `run` 必须抛出错误，原因与 `validateParams` 的返回相同。

## 场景

- WHEN 直接映射、4 行、每块 2 字、地址 5 位，依次读 6、7、22、6 THEN 结果是 缺失、命中、缺失（换出块 3）、缺失（换出块 11）。
- WHEN 同一串地址改成 2 路组相联加 LRU THEN 第 4 次访问命中，块 3 在行 2，块 11 在行 3。
- WHEN LFU 发生一次替换 THEN 这一步之后候选各行的计数器都是 0。
- WHEN 写过的块被换出 THEN 解题表「换出」一栏带「（写回）」。
- WHEN 连续两次访问同一个块 THEN 第二次命中，且不出预测题。
- WHEN `mapping` 是 `组相联` 而没给 `rowsPerSet` THEN `run` 抛出错误。

## 性质

1. 命中次数 + 缺失次数 = 访问次数。
2. 块已经在 cache 里就一定命中，不在就一定缺失。
3. v = 1 的组相联逐步与直接映射相同；u = 1 的组相联与全相联相同（只差 `access.index`，后者为 null）。
4. 与独立写的朴素参照实现逐次一致：命中、所在行、换出的块、写回。
5. LRU 不换出本组最近用过的那一行。
6. 同样的参数得到完全相同的 Trace，`validateTrace` 为空。

固定用例：`evals/golden/cache-run.json` 的三个手算例（直接映射冲突、同一串地址的 2 路组相联、全相联 LFU 带写和访问时间）；例 3.4 的数值（p101）和例 3.5–3.7 的字段位数（p107–108）写在测试里。
不做：FIFO、缺失分类、cache 总位数、全写法和写一次法、多级 cache。

## 待确认

- LRU 的「其他各行加 1」教材没说范围，这里只加同组的行。整个 cache 都加时换出的行相同，计数值不同。
- LRU 的计数规则教材只写了命中。调入时这里按刚用过处理，否则新行得不到保护。
- LFU 新行从 0 计数，引起调入的那次访问不算在内。
- LFU 计数并列、候选行有多个空行时教材没有规定，这里都取行号最小的。并列时可能连续换出同一行。
- 2 路组相联用一个二进制位代替计数器的做法（p108）没有单独建模。
- 写策略固定为写回法，是否可选留给 3-cache-write。
- 第 5 步兼作 `access` 步。播放器如果要在 5 个讲解步之后另有一个汇总步，再拆。
- h 写成「3/7 ≈ 0.4286」，t_a 带 ns，e 写成百分数。页面判分要数值时用 `performance()`。
