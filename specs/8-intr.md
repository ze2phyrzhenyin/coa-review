# 8-intr：单级中断一次完整过程引擎

困惑：关中断、保存断点、保存现场、开中断，各由谁做，先后是什么。学完能按图 8.6 的次序写出一次中断从请求到返回的每一步，并标出硬件还是软件。
教材依据：图 8.6 流程和四点说明（p264–266）；图 8.9 接口的 BS、RD、EI、IR、IM 与过程 ①–⑩（p267–268）；单级中断与串行排队链（p268–270，图 8.10、8.11）；向量中断（p266，图 8.7）。
代码：`src/engines/intr/model.ts`，入口 `run(params)`；另有 `validateParams`、`generate(seed)`。

## 参数

| 名 | 取值 | 说明 |
|---|---|---|
| `devices` | 1–4 项 `{ name, ei, rd, vector, entry }` | 链上次序，第 0 个离 CPU 最近（p268）；`rd` 为 1 表示这条指令执行期间设备准备好了；`vector` 向量地址、`entry` 服务程序入口，0–FFFFH |
| `im` | 0 或 1 | 请求到来时的 IM；1 = 关中断（p267） |
| `pc` | 0–FFFDH | 正在执行的那条指令的地址；一条指令占一个地址（IM=1 时断点是 pc+2） |
| `regs` | 1–3 项 `{ name, value }` | 服务程序要用、因而要保存的寄存器 |
| `data` | 0–255 | 设备缓冲寄存器里的数据 |

## 要求

1. 初始：`rd` 为 1 的设备 BS=1、RD=0（已启动，未就绪）；IR=0。
2. 步序必须是：设备就绪 RD 置 1（④）；EI=1 的接口发请求（⑤）；执行完当前指令 PC 加 1（指令周期）；公操作查请求线，IR 置 1（⑥）；查响应条件；然后图 8.6 的中断周期：响应中断发 INTA、关中断 IM 置 1、找出中断源（INTA 沿链传，第一个有请求的接口截住并送出向量地址）、保存断点（PC 进栈）、取入口地址并转移；然后服务程序：保存现场、设备服务（读数据 ⑨，C 信号使 BS、RD 复位 ⑩）、恢复现场、开中断 IM 清 0、中断返回（断点出栈送 PC）。
3. 中断周期的五步由硬件完成，是中断处理的隐操作（p266；统考叫中断隐指令）；前四步是 `explain`，转移那一步是 `cycle`。服务程序的五步由软件完成，每步是 `instruction`。
4. 单级中断的服务程序里，保存现场之后没有开中断这一步；开中断只在恢复现场之后（p265、p268）。
5. 响应条件：IR=1、IM=0、当前指令已执行完（p265、p268）。IM=1 时这一次不响应：下一条指令是开中断指令，执行后 IM=0、PC 再加 1，回到公操作重新检查。
6. 没有设备同时满足 RD=1、EI=1 时，请求线一直为 0，执行完当前指令后结束，没有中断周期。
7. 响应时 IR 清 0。被截住的设备之外仍有请求的，最后加一步说明：返回后下一条指令结束时 IR 会再置 1。
8. 状态必须是：`phase`（主程序 / 中断周期 / 服务程序）、`pc`、`im`、`ir`、`line`（请求线）、`inta`、`devices[i]` 的 `bs` `rd` `ei` `chain`（INTA 到没到这个接口）、`selected`、`vector`、`regs`（名 → 值）、`stack`（`{ what, value }`，栈顶在末尾）、`box`（当前这一步的名字，依次取 设备就绪、发出请求、执行指令、中断？、响应条件、[开中断指令、中断？、响应条件]、响应中断、关中断、找出中断源、保存断点、转移、保存现场、设备服务、恢复现场、开中断、中断返回、[还有请求]；方括号里的只在 IM=1 或仍有请求时出现）。
9. 预测题：响应条件那一步问「CPU 这时响应吗」；关中断、保存断点、保存现场三步问「这一步由谁完成」（硬件 / 软件）；找中断源那一步在有两个以上设备请求时问「哪个接口截住 INTA」。
10. `table` 列为 次序 | 操作 | 谁做 | IM | PC | 栈顶，从执行完当前指令起每步一行。
11. `result` 必须有 响应的设备、断点、向量地址、入口地址、硬件完成、软件完成、返回后 PC、返回后 IM；有没被服务的请求时加 仍在请求。没有中断时只有 响应的设备 = 无 和 PC。
12. 地址写成大写十六进制加 H。参数不合格时 `run` 抛出错误，原因与 `validateParams` 相同。

## 场景

- WHEN 两台设备都就绪、都 EI=1 THEN 离 CPU 近的被响应，另一台列在 仍在请求。
- WHEN IM=1 THEN 先执行一条开中断指令，断点比 IM=0 时大 1。
- WHEN 唯一就绪的设备 EI=0 THEN 没有中断周期。
- WHEN 中断返回之后 THEN 栈空，寄存器与初始相同（数据寄存器除外的现场全部恢复），IM=0。

## 性质

1. 返回后栈空、PC = 断点、IM = 0、寄存器恢复为初值。
2. 被响应的是链上第一个 RD=1 且 EI=1 的设备。
3. 关中断在保存断点之前，保存断点在转移之前，转移在保存现场之前；开中断在恢复现场之后、返回之前；硬件步全在软件步之前。
4. 保存现场进栈的次序与恢复时出栈的次序相反。
5. 同样参数同样 Trace，`validateTrace` 为空；与朴素参照的步序、断点、入口一致。

固定用例：`evals/golden/intr-cases.json`，手算（两台设备都请求、IM=1 先开中断、EI=0 不请求）。
不做：多级中断和屏蔽寄存器（见 8-mask）、查询中断的软件识别（图 8.8）、中断饱和时间（8-saturate）、DMA。
