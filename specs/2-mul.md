# 2-mul：阵列乘法引擎（无符号、原码、补码）

困惑：补码相乘为什么先变绝对值，算后求补什么时候做。学完能画出位积矩阵，按图 2.7 的全加器阵列算出 2n 位积，用带求补器的阵列乘法器求 [x×y]原、[x·y]补，并会算 (8n−4)T。
教材依据：2.3（p43–48）：位积矩阵 p44，图 2.6、2.7 与式 2.26 p45–46，例 2.22 p46，对 2 求补器图 2.8 与式 2.27 p46–47，图 2.9 p47，例 2.23、2.24 p47–48。
代码：`src/engines/mul/model.ts`，入口 `run(params)`、`generate(seed, options)`。

## 参数

| 名 | 取值 | 说明 |
|---|---|---|
| `mode` | `无符号` `原码` `补码` | |
| `n` | 2–8 的整数 | 阵列是 n 位 × n 位；带符号时操作数是 n+1 位（符号位加 n 个数值位） |
| `x`、`y` | `{ as: '真值', text }` 或 `{ as: '机器数', bits }` | 只用定点整数；无符号时真值不带负号，机器数是 n 位 |

## 要求

1. 无符号：A = a_{n−1}…a_0，B = b_{n−1}…b_0，积 P = p_{2n−1}…p_0（p44）。带符号：A、B 是两个算前求补器的输出 |x|、|y|（p47 图 2.9）。
2. 位积 a_i·b_j 必须一步由与门同时产生，共 n² 个；p_0 = a_0b_0 直接输出（p44–45）。
3. 全加器阵列必须照图 2.7 连线：共 n 行、每行 n−1 个全加器，`rows[r][k]` 的权是 r+1+k。前 n−1 行（r 对应 b_{r+1}）：上方入口是 r = 0 时的 a_{k+1}b_0，或上一行同权的和，最左一个接 a_{n−1}b_r；右方入口是 a_k·b_{r+1}；斜入口是上一行低一权的进位（第一行接 0）。第 n 行是行波进位加法器：上方是上一行同权的和（最左接 a_{n−1}b_{n−1}），斜入口是上一行低一权的进位，右方是右邻的进位（最右接 0）。全加器总数 n(n−1)（p45）。
4. p_j（1 ≤ j ≤ n−1）是第 j 行最右全加器的和；p_n…p_{2n−2} 是最后一行的和；p_{2n−1} 是最后一行最左的进位输出。
5. 步骤顺序：带符号时先写 [x]、[y]，再算符号位 p_{2n} = x_f ⊕ y_f，再过 x、y 两个算前求补器；与门产生位积；前 n−1 行每行一步（同一行的全加器同时工作）；最后一行每个全加器一步（进位从右往左传）；带符号时过算后求补器；拼出积；最后讲延迟。位积、全加器行、行波每一位、求补器的步层级是 `beat`（阵列的一级，没有时钟），其余是 `explain`。
6. 对 2 求补器必须按式 2.27 前的逻辑式算：C_{−1} = 0，C_i = a_i + C_{i−1}，a_i* = a_i ⊕ E·C_{i−1}；状态里要有扫描链 C 和使能 E（p46）。
7. 补码：算前求补器 E 取各自的符号位；算后求补器 E = x_f ⊕ y_f（p47）。原码：三个求补器 E 都是 0，原样通过（p47「原码乘法中……都不需要」）。
8. 延迟必须按式 2.26 写出 t_m = T_a + (n−1)×6T + (n−1)×T_f + 3T = (8n−4)T，T_a = T、T_f = 2T，并在状态 `path` 里列出最长路径：权 n−1 那一列竖直穿过前 n−1 行，再沿最后一行的进位走到 p_{2n−2}（p45）。补码只加一句：教材说总时间约为原码阵列乘法的 2 倍，不另给式子（p47）。
9. 预测题两道，答案取自状态：最后一行最左全加器那一步问 p_{2n−1}（`bits`）；补码时算后求补那一步问 E（`choice`：求补、直通），无符号和原码时第一行那一步问 p_1（`bits`）。
10. `table` 是纸面竖式（例 2.22–2.24 的版式）：列为 行名、（带符号时）符号、2^{2n−1}…2^0、说明。行：[x]、[y]、符号位、|x|、× |y|（无符号是 A、× B），n 行位积（第 j 行占 2^{j+n−1}…2^j 列），和，算后求补，积。每行指回写出它的一步。
11. `result`：`乘积`（无符号是 P；原码是 [x×y]原，补码是 [x·y]补，2n+1 位）、`真值`、`十进制`、`延迟`。
12. 参数不合格抛 `BitsError` 并说明原因：n 不在 2–8、模式不认识、位数不对、真值超出范围、无符号带负号；补码里出现 −2^n（n 位求补器给不出它的绝对值）；补码里一个操作数是 0、另一个是负数（算后求补后符号位会是 1，积成了 −2^{2n}）。

## 场景

- WHEN 无符号、n=5、A=11011、B=10101 THEN 位积第 1、3 行全 0，P = 1000110111，十进制 567（例 2.22）。
- WHEN 原码、x=+1111、y=−1101 THEN 符号位 1，求补器全是直通，积 111000011，−195（例 2.23）。
- WHEN 补码、[x]补=10001、[y]补=10011 THEN |x|=1111、|y|=1101，算后求补 E=0，积 011000011，+195（例 2.24）。
- WHEN 补码、x=+1011、y=−0110 THEN 算后求补 E=1，01000010 变成 10111110，积 110111110。
- WHEN n=5 THEN 延迟 36T，`path` 有 4 + 4 个全加器。
- WHEN 补码、x=−10000、n=4 THEN 抛错。

## 性质

1. 任意合法参数：P 按无符号读等于 |x|·|y|；带符号时 `乘积` 按原码或补码解码等于 x·y。
2. 每个全加器满足 2·carry + sum = top + right + diag。
3. 每一步之后：已输出的 p 位、最新一行的和与进位、还没进阵列的位积，按权相加等于 A·B。
4. 求补器输出等于「从右找到第一个 1，左边取反」，也等于取反加 1（E=1 时），E=0 时等于输入。
5. 同样的参数得到同样的 Trace；`validateTrace` 为空；`generate(seed)` 同种子同参数，且总能 `run`。

固定用例：`evals/golden/mul-cases.json`：例 2.22、2.23、2.24（p46–48），习题 7 两组数的原码、补码（p68），自拟走查数，n=2 的小例子。
不做：Booth、补码一位乘、原码一位乘的部分积迭代表（教材没有，p44 说串行乘法器已淘汰）；直接补码阵列乘法（只在二维码资料和解析计算 15）；m ≠ n 的阵列；定点小数写法；用先行进位代替最后一行。
